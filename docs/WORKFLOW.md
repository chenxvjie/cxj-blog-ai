# 实施与交付流程

## 仓库边界

cxj-blog-front：问答面板、流式展示、停止生成、引用。
cxj-blog-backend：登录、额度、会话归属、公开版本管理、索引任务、AI内部调用与流式转发。
cxj-blog-ai：FastAPI、LangGraph、分块、托管Embedding、检索、DeepSeek回答、引用验证。

## 阶段与验收

1. 基础服务：固定Python版本、锁定依赖、健康接口、内部认证、无密钥测试、Dockerfile；健康仅证明进程正常，就绪检查单独展示模型配置和数据库状态，不能假装问答已可用。
2. 平台接入：GitHub推送与PR；云效克隆、检查、测试、构建可追溯制品；生产部署手动确认，模拟测试不调用付费API。
3. 内容同步：Java发布事务写索引任务；worker领取并重试，解析指定公开版本。按版本与切分规则去重，写新批次并核验当前版本后切换。
4. 检索：中文关键词与1024维稠密向量混合检索，公开状态和版本过滤，按评测调整候选数。
5. 回答：LangGraph问题处理→检索→证据判断→必要时补检索一次→DeepSeek生成→引用验证。无足够证据时说明不足；不得伪造回答或降级成无依据闲聊。
6. 联调：后端鉴权/配额、前端流式/取消、引用、错误处理、管理员索引状态。

## 文章规则

仅索引公开文章；草稿和待审核版本不纳入。已发布文章修订待审核时使用原公开版；新公开版替换索引；下架和删除立即停止检索。检索和输出引用都核验公开状态与版本，缓存命中也必须核验。索引异步失败不阻塞文章发布。

## 托管模型边界

DeepSeek与Embedding分别配置地址、模型名、密钥和超时。bge-m3服务商确认后检查认证方式、批量限制、维度、输入长度、响应格式、计费及数据处理政策。托管商即使提供OpenAI兼容接口，也必须进行真实契约验证。任何向量维度不符、非有限值或空响应均拒绝入库；更换模型空间须完整重建索引。

## 部署

拟新增ai API容器与ai-worker容器，共用同一镜像，通过内部网络调用，不暴露公网端口。第一版可按资源决定是否暂合并进程，但任务必须可重试且不可丢失。健康检查、资源限制、共享部署锁与日志脱敏齐备后再上线。Java统一处理外部登录，AI使用内部认证和有限权限账号。

云效构建产物不包含.env或密钥；服务器不git pull。依赖在构建阶段锁定并准备，部署时无需临时从GitHub获取源码。可信主机部署脚本单独安装，Git推送不自动替换。镜像以提交/制品摘要追溯。

## 数据迁移

博客表和索引任务表由Flyway负责；AI专用schema由一套明确的迁移工具负责，同表禁止双重迁移管理。现有postgres镜像的pgvector支持、数据卷、备份恢复必须先验证。上线顺序为基础设施→兼容后端→AI与索引→前端开关。

## 已确认与当前边界

DeepSeek官方API，模型deepseek-flash；SiliconFlow BAAI/bge-m3，固定1024维。游客每天10次、登录用户20次、管理员不限每日次数，由Java后端执行。最近三轮历史仅用于检索问题改写，不持久化对话正文。

已实现事务索引任务、租约恢复和五次退避重试；真流式模型分块经LangGraph、FastAPI和Java转发，校验成功确认，失败或完成前断连退还额度。当前生产准备与首次发布流程见FLOW.md。

尚未实现管理员可视化索引面板、长期预算管理和持久化会话。首次Linux构建、生产索引覆盖与前后端上线联调待验收。
